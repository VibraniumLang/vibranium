# Safety-relevant CS IDs for the invalid-program mutation oracle (docs/MUTATION.md): a severity class, not a waiver list.
# The contract: a C#-invalid program (a genuine C# error, default severity Error, or a warning that Vibranium.App.props
# promotes explicitly) must be rejected by every frontend, including standalone vib-self and native vib-stage2.
# Accepting one is a defect whatever its IDs. This class sets release priority: a self accept under one of these IDs is
# P1, or P0 when asan mode shows a memory error (or invalid IR). Acceptance of these IDs could break memory or type
# safety, ownership/linearity or a Std/Core invariant (access, readonly, in/this writes, definite assignment,
# layout-relevant constraints, value reinterpretation, control flow that could emit malformed code).
# Format: ID<TAB>likely self component<TAB>why it is safety-relevant. Components: parser, binder (declarations/types),
# lowerer (expression binding, conversions, access, control flow), checker (flow analysis). An ID in neither severity
# file is unclassified and is treated as safety-relevant.
